## 1. 一局的骨架

```
[先古之民] → 第1排(必为敌人) → … → 倒数第7排(必为宝箱) → … → Boss前一排(必为休息处) → [Boss]
   row 0                row 1                row L-7                     row L-1               row L
```

| 项 | 规则 | 出处 |
|---|---|---|
| 幕数 | 3 幕（Index 0/1/2），第 1 幕在密林（Overgrowth）与暗港（Underdocks）中二选一 | 见第 04 章 |
| 房间数 | 密林/暗港 15、巢穴（Hive）14、荣耀（Glory）13；多人 −1 | `Models.Acts/Overgrowth.cs:47`、`Hive.cs:47`、`Glory.cs:43`；`Models/ActModel.cs:261` |
| 楼层数 | 房间数 + 2（加先古之民层与 Boss 层） | `Models/ActModel.cs:276` |
| 起点 | 地图 row 0 的单点，类型 `Ancient`，进去是本幕先古之民事件 | `Map/StandardActMap.cs:301` |
| 首局特例 | 时间线「涅奥」纪元未揭示时，第 1 幕起点改成**怪物房**（不见涅奥） | `Runs/RunManager.cs:589,831` |
| 进阶 10「双重Boss」 | 第 3 幕 Boss 后再挂一个 Boss 点 | `Map/StandardActMap.cs:98`；`Runs/RunManager.cs:769` |
| 终局 | 第 3 幕 Boss 不发奖励，进入尾声事件建筑师（The Architect / `TheArchitect`，战斗式布局的对话事件） | `Rewards/RewardsSet.cs:91`；`Runs/RunManager.cs:1333` |

## 2. 地图生成算法（StandardActMap）

### 2.1 网格与路径

| 步骤 | 做法 | 出处 |
|---|---|---|
| 网格 | `Grid = new MapPoint[7, 房间数+1]`；Boss 在 (3, L)，起点在 (3, 0)，二者不在网格里 | `Map/StandardActMap.cs:89-99` |
| 撒路径 | 循环 7 次：在 row 1 随机选一列作起点（**第 2 条强制和第 1 条不同列**，生成阶段保证至少两个入口；剪枝可能删掉 row 1 的点，复刻 300 张第 1 幕图里有 3 张最后只剩 1 个入口），然后一路向上生成到 row L−1 | `StandardActMap.cs:206-232` |
| 每步走向 | 在 {左上, 正上, 右上} 里**稳定洗牌**后依次尝试；贴边时左/右被钳到本列（所以边缘列更容易走直线） | `StandardActMap.cs:145-181` |
| 防交叉 | 想往斜向走时，检查同排相邻点是否已有反向斜边，有就换方向——保证连线永不交叉 | `StandardActMap.cs:183-204` |
| 接头尾 | row L−1 的点全部连向 Boss；row 1 的点全部挂在起点下 | `StandardActMap.cs:220-232` |
| 随机流 | 专用流 `Rng(种子, "act_{幕+1}_map")`，与玩法 RNG 隔离（RNG 体系见第 1 章） | `StandardActMap.cs:111-114` |

7 条路径大量合流，实际节点远少于 7×15。复刻模拟（§2.5）里第 1 幕平均 66.7 个点，剪枝后 59.7 个。

### 2.2 房间类型配比（MapPointTypeCounts）

| row L−1 | 休息处 | 第 15 房（Boss 前） | `StandardActMap.cs:249-253` |

**撒点总量**（每幕独立抽）：

| 类型 | 第 1 幕 密林/暗港 | 第 2 幕 巢穴 | 第 3 幕 荣耀 | 出处 |
|---|---|---|---|---|
| 精英 | 5（进阶 1「精英蜂拥」×1.6 → 8） | 同 | 同 | `Map/MapPointTypeCounts.cs:15` |
| 商店 | 3 | 3 | 3 | `MapPointTypeCounts.cs:18` |

`NextGaussianInt` 是「四舍五入后不在区间就重抽」的拒绝采样（`Random/Rng.cs:262`），等价于截断正态。精确分布（`ch05_build_tables.py` 算）：

|---|---|---|

| 第 1 幕休息 Gauss(7,1)[6,7] | 6:38.7% / 7:61.3% | 6.61 |
| 第 2 幕休息 Gauss(6,1)[6,7] | 6:61.3% / 7:38.7% | 6.39 |

**放置规则**（`IsValidPointType`，`StandardActMap.cs:404-485`）：

| 规则 | 约束 | 设计意图（推断） |
|---|---|---|
| 下层禁区 | row < 6（前 5 房）不放休息处、精英 | 开局先打普通怪攒牌，不让人一上来就撞精英或白休息 |
| 上层禁区 | row ≥ L−3 不放休息处（Boss 前一排的固定休息处除外） | 避免「休息-休息-Boss」连续回血 |
| 不连续 | 精英/休息处/宝箱/商店 不能与父节点或子节点同类型 | 防止连续两个商店、两个精英 |
| 兄弟互斥 | 休息处/敌人/未知/精英/商店 不能与「同父节点的其他子节点」同类型 | **保证每个分叉的选项不同** |

撒点流程：把「休息×N、商店×3、精英×5、未知×U」排成队列，对全部空位洗牌后逐个分配；当前队首不合法就转到队尾试下一个，整队都不合法就先空着，最多扫 3 轮，剩余空位全填敌人（`StandardActMap.cs:273-298,363-401`）。扫完仍没放下的类型会被丢弃，由下一步的修复补回——但修复是拿**全图该类型总数**对比目标（`MapPathPruning.cs:52-58`），休息处的计数包含 Boss 前那一整排固定休息处，所以休息处实际上补不回来（商店/精英/未知能补）。

注意：最后「填敌人」这一步**不检查规则**，所以兄弟互斥实际上只约束了特殊房；两个相邻的敌人分叉仍可能出现，这正是剪枝要处理的对象。

### 2.3 剪枝 MapPathPruning：消灭「假选择」

源码注释：「Detects and removes duplicate path segments ... that share the same sequence of point types」（`Map/MapPathPruning.cs:12`）。

| 概念 | 定义 | 出处 |
|---|---|---|
| 片段起点 | 有 ≥2 个子节点的点（或 row 0 起点） | `MapPathPruning.cs:IsValidSegmentStartMapPoint` |
| 片段终点 | 有 ≥2 个父节点的点（合流点） | `IsValidSegmentEndMapPoint` |
| 片段键 | 起点坐标 + 终点坐标 + 途经房型序列；从起点出发的片段不记起点列 | `GenerateSegmentKey` |
| 重复 | 同一个键下有 ≥2 条**中间不共用节点**的片段 | `AddSegmentsToDictionary`、`OverlappingSegment` |

找到重复后：随机打乱，删到只剩最后一条（只删「单进单出、删了不会让别人断路」的点）；删不动就砍掉分叉点到下一个点的一条边。循环直到没有重复（>50 轮抛异常）。剪完再 `RepairPrunedPointTypes`：商店/精英/休息/未知数量不足的，从「可修改的敌人点」里挑合法的改过去；修复可能制造新重复，所以「剪→补」最多来回 3 次（`MapPathPruning.cs:22-50`）。

**设计观察**：地图选择的价值在于「两条路不一样」。二代在生成器里直接定义了什么叫「一样」——同一个分叉、同一个合流、同一串房型——并把它删掉。这比一代靠视觉/随机自然稀释要硬核：玩家在地图上看到的每一次分叉，**至少有一个房间类型不同**。

### 2.4 后处理 MapPostProcessing（只改观感）

三个函数只挪列坐标，不改拓扑与类型（`Map/MapPostProcessing.cs`；作者注释说跑完 0 ms）：

| 函数 | 作用 |
|---|---|
| `CenterGrid` | 左边两列或右边两列全空时整体平移 1 列，让图居中 |
| `SpreadAdjacentMapPoints` | 同排节点在连线允许范围内挪到「离最近邻居最远」的位置 |
| `StraightenPaths` | 单进单出且两侧都在同一侧的「折角」点往里拉直 |

**可借鉴**
- 「总量固定 + 局部规则 + 去重剪枝」三段式：总量控经济，局部规则控节奏，剪枝保证选择有意义。

- 固定排（第 1 房打怪、中段宝箱、Boss 前休息）给每幕一个稳定的节拍骨架，随机只在骨架之间发生。

### 4.2 卡牌稀有度与保底（CardRarityOdds）

判定：掷 `r`；`r < 稀有基础 + 偏移` → 稀有；`r < 罕见 + 上一项` → 罕见；否则普通（`Odds/CardRarityOdds.cs:96-111`）。罕见区间从「稀有+偏移」处起算，所以稀有+偏移为负时罕见也被吃掉同样多：普通战斗刚出完稀有（偏移 −5%）时稀有 0%、罕见 35%、普通 65%；下表的「罕见 37%」只在稀有+偏移 ≥ 0 时成立。

| 来源 | 稀有 | 罕见 | 普通（剩余） | 进阶 7「稀缺」（Scarcity） |
|---|---|---|---|---|
| 普通战斗 | 3% + 偏移 | 37% | 60% − 偏移 | 稀有 1.49% |
| 精英 | 10% + 偏移 | 40% | 50% − 偏移 | 稀有 5% |
| Boss | 100%（偏移按 0） | 0 | 0 | — |
| 商店 | 9% + 偏移（只读不写） | 37% | 54% − 偏移 | 稀有 4.5% |
| Uniform | 不分稀有度，池内等权 | | | |

**保底偏移**：初值 −5%；每出一张非稀有 +1%（稀缺 +0.5%），上限 +40%；出稀有回到 −5%（`CardRarityOdds.cs:27-31,70-81`）。只有「来源=战斗 且 赔率类型∈普通/精英/Boss」（或带 `ForceRarityOddsChange` 标志，目前只有修饰符 SealedDeck）会推进偏移；大多数事件/遗物给的卡走 `RollWithBaseOdds`，既不吃保底也不消耗保底（`Factories/CardFactory.cs:246-262`）。例外：捕梦网（休息时给一份卡）、转经轮（普通战斗额外一份）、白星（精英额外一份、Boss 赔率）用 `CardCreationOptions.ForRoom` 生成，来源算「战斗」，同样读写保底（`Models.Relics/DreamCatcher.cs:22`、`PrayerWheel.cs:24`、`WhiteStar.cs:29`）。每张卡各掷一次，所以一份 3 选 1 奖励内部也会推进偏移。

长期实际稀有率（蒙特卡洛，每份奖励 3 张，`ch05_build_tables.py`）：

| 场景 | 每张卡稀有率 | 一份奖励至少 1 张稀有 | 平均多少张出 1 稀有 |
|---|---|---|---|
| 全打普通战斗 | 6.57% | 19.7% | 15.2 |
| 全打普通 + 稀缺 | 3.93% | 11.8% | 25.4 |
| 全打精英 | 10.86% | 30.9% | 9.2 |
| 全打精英 + 稀缺 | 5.43% | 16.3% | 18.4 |

名义 3% 的稀有率被保底放大到约 2.2 倍；稀缺进阶同时砍基础值和增长速度，实际稀有率几乎腰斩。

**与一代对比（凭公开知识）**：一代的保底只在抽到**普通**时累加；二代代码是「非稀有」都累加（`CardRarityOdds.cs:76-79` 的 else 分支），保底来得更快。

稀有度不可用时（池里没有该稀有度）按 普通→罕见→稀有→普通 循环找下一个（`Entities.Cards/CardRarityExtensions.cs:14`；`CardFactory.GetNextAllowedRarity`）。

**抽取机制**：

1. 开局时每幕把「本幕事件 + 18 个通用事件」去掉未解锁的（纪元 Event1/2/3 分别锁垃圾堆、镜中倒影、色彩哲学家），洗牌成一个队列（`Models/ActModel.cs:331-360`；`Timeline.Epochs/Event{1,2,3}Epoch.cs`）。

**IsAllowed 的几类门槛**（全部条件见 `ch05_events_detail.csv` 的 `is_allowed` 列）：

**多人**：有 8 个事件标 `IsShared`（全队同一个实例，如茂密的植被、商人？？？、灯火钥匙），其余每人一份（`Models/EventModel.cs:81`）。事件随机数种子 = 局种子 +（非共享时）玩家位次 + 事件名哈希（`EventModel.cs:234`）——同一种子里，事件用自己这条 RNG 掷的结果（如水晶球报价、传送带菜品、滑脚木桥抽中的牌）与你何时走到它无关；但很多事件发遗物走 `RelicFactory.PullNextRelicFromFront(Owner)`（稀有度用玩家奖励流、遗物从遗物袋队头取，如审判、长者兰伟德、遗物交换商），这部分仍取决于之前拿过什么。

### 9.2 结构：页面与选项

事件是「页面（page）+ 选项（option）」的状态机：`GenerateInitialOptions` 给出首页选项，每个选项回调里要么 `SetEventState(新描述, 新选项)` 翻页，要么 `SetEventFinished` 结束（`Models/EventModel.cs:526`）。本地化 key 规则 `<事件>.pages.<页>.options.<选项>.title/description`（`localization/zhs/events.json`）。

| 统计（57 个池内事件 + 建筑师 + 占位） | 值 |
|---|---|
| 首页 2 个选项 | 36 个 |
| 首页 3 个 | 8 个 |
| 首页 4–7 个（含「锁定」灰选项） | 9 个 |
| 首页 0–1 个（自定义布局/单选项） | 6 个 |
| 页面数最多 | 深渊浴场 15、审判 11、滑脚木桥 10、真理石板 9 |

`EventOption` 的修饰器把致死风险显式化：`ThatDoesDamage(n)`（当前 HP ≤ n 时）和 `ThatDecreasesMaxHp(n)`（最大 HP ≤ n 时）都只是 `ThatWillKillPlayerIf(...)` 的快捷写法，条件成立时按钮闪红警示；扣多少血本身写在选项文案的变量里，不是这几个方法标的（`Events/EventOption.cs:199-222`）。条件不满足的选项以「锁定」形态显示而不是隐藏（如长者兰伟德「你没有任何可以给他的药水」），玩家能看到自己错过了什么。

### 9.4 设计精选

**① 深渊浴场（Abyssal Baths，暗港）——递增代价的「再泡一会」**
每泡一次 +2 最大 HP，同时受到 3、4、5……点伤害（每次 +1）；不泡则回 10 HP。泡 n 次累计 +2n 上限、当前 HP 净变化 −n(n+1)/2。当下一次会致死时切到「死亡警告」页（仍允许继续）。15 个页面里 LINGER1–9 是逐次升级的叙述。（`Models.Events/AbyssalBaths.cs:13,64-107`）
→ 推运气（push-your-luck）的最简模板：收益线性、代价递增、何时停由玩家定。

**② 真理石板（Tablet of Truth，密林）——几何递增 + 孤注一掷**
解读：扣最大 HP 3 → 6 → 12 → 24，各随机升级 1 张牌；第 5 次扣到只剩 1 点上限，换**全牌组升级**。砸碎：回 20 HP。（`TabletOfTruth.cs:GetDecipherCost,LoseMaxHpAndUpgrade`）
→ 末档奖励质变（单张→全体），让「坚持到底」成为一种构筑路线而不是纯亏。

**③ 滑脚木桥（Slippery Bridge，通用，第 7 层后）——反向删牌**
默认结果是**失去牌组里一张随机非基础牌**（选项上悬浮显示是哪张）；「抓住」花 3、4、5…点 HP 重抽要丢的那张，已跳过的不会再抽到；注意只有第一次抽限定非基础牌，重抽的候选是牌组里除当前这张同名牌外的所有可移除牌（含打击/防御等基础牌）（`SlipperyBridge.cs:106-130`）。（`SlipperyBridge.cs:CurrentHpLoss,GetNewRandomCard`）
→ 把一代常见的「付费删牌」反转成「付费保牌」，玩家对牌组价值的判断被直接拿来定价。

**④ 审判（Trial，荣耀）——随机被告 + 一个真退出按钮**
接受后随机三种被告之一（商人/贵族/无名氏），判有罪或无罪各对应「诅咒 + 奖励」组合：如商人有罪 = 悔恨诅咒 + 2 个遗物、商人无罪 = 羞耻 + 升级 2 张、贵族无罪 = 悔恨 + 300 金、无名氏无罪 = 疑虑 + 变化 2 张。拒绝后可「加倍下注」，它会弹出**放弃本局**的确认框。（`Trial.cs:Accept,Merchant*/Noble*/Nondescript*,DoubleDown`）
→ 选项文案即叙事；用系统级按钮（弃局）做事件笑点，是很少见的「打破第四面墙」。

**⑤ 无尽传送带（Endless Conveyor，暗港，≥120 金）——金币扭蛋**
每盘 40 金，按权重随机上菜：鱼子酱 +4 最大 HP（权 6）、蚌肉卷回 10（6，满血不出）、香辣薄脆升级随机牌（3）、水母肝变化 1 张（3）、炸鳗鱼得 1 张无色卡（3）、可疑调味料得药水（3，药水栏满不出）、金色异鱼**免费**且 +75 金（1，第 2 盘起）；**每第 5 盘固定**是海洋混混沙拉（得疯狂进食）；同一道菜不连上；钱不够按钮锁定。另一个选项「观察主厨」直接免费升级 1 张。（`EndlessConveyor.cs:RollDish`）
→ 把金币转化成「可预期的随机」，第 5 盘保底和不连菜规则都是扭蛋手感设计。

**⑥ 巨大花卉（Colossal Flower，巢穴）——三段式掏宝**
直接采 35 金；深入一次（−5 HP）后可采 75；再深入（−6）可采 135；第三次深入（−7）改拿遗物花粉核心。（`ColossalFlower.cs:_prizeCosts,_prizeDamage`）
→ 金币收益 35→75→135 接近翻倍，伤害只 +1，后段性价比递增，鼓励「一次走到底」。

**⑦ 欢迎来到旺购百货（Welcome to Wongo's，第 2 幕，≥100 金）——跨局积分的讽刺**
特价箱 100 金得普通遗物、特选商品 200 金得指定稀有遗物、神秘盲盒 300 金得「5 场战斗后给 3 个遗物」的票；**什么都不买离开会随机降级一张已升级的牌**。每次购买给旺购积分（特价 32、特选 16、盲盒 8——越贵越少），积分存在**存档进度**里跨局累计，满 2000 发一个「没有任何作用」的客户感恩徽章。（`WelcomeToWongos.cs:_wongoPointsForBadge,CheckObtainWongoBadge,Leave`；`Saves`：`SaveManager.Instance.Progress.WongoPoints`）
→ 用机制本身讽刺会员积分：积分规则反向、奖品无用、不消费有惩罚。

**⑧ 商人？？？（Fake Merchant，第 2 幕起，单人）——假商店**
货架是 9 件仿冒遗物（锚？？？、小血瓶？？？、异蛇之眼？？？、古茶具套装？？？……都是一代经典遗物名加问号）洗牌取 6，一律 50 金；向他扔恶臭药水（Foul Potion）会开战，赢了拿全部未售仿品 + 商人的地毯（「低劣的仿制品。没有任何作用」）。出现条件是金币 ≥100 **或**身上有恶臭药水。（`FakeMerchant.cs:7-20,IsAllowed,FoulPotionThrown`；`Models.Relics/Fake*.cs:MerchantCost=50`）
→ 复用商店 UI 做事件；用一代遗物的「仿品」给老玩家埋梗。

**⑨ 灯火钥匙 → 战史学家（The Lantern Key → War Historian Repy）——跨幕任务**
第 2 幕的灯火钥匙：交还得 100 金，或留下并和神秘骑士战斗，赢了得任务卡灯火钥匙。持有它进入第 3 幕后：? 只出事件，且**下一个事件被强制替换为战史学家 付袭**——两个选项都会收走钥匙（`WarHistorianRepy.cs:102-131`），之后 ? 恢复正常，所以实际效果是「第 3 幕第一个 ? 必为战史学家」（该事件自身 `IsAllowed=false`，只能这样进入），可以开笼（历史课）或开宝箱（2 药水 + 2 遗物）。（`TheLanternKey.cs`；`Models.Cards/LanternKey.cs:14-36`；`WarHistorianRepy.cs:30`）
同类还有**传说是真的 → 藏宝图**（第 1 幕拿图，第 2 幕地图变沙漏形，宝箱 +600 金，§2.6）。
→ 用一张「不可打出的任务卡」做跨幕存档与钩子，通过 `ModifyUnknownMapPointRoomTypes` / `ModifyNextEvent` / `ModifyGeneratedMap` 三个 Hook 改写后续内容，任务系统零新增框架。

**⑩ 多尼斯异鸟巢（Byrdonis Nest，密林）——宠物线**
吃蛋 +7 最大 HP，或带走蛋（卡）；蛋能在休息处「孵化」（§6），且「已有事件宠物」时本事件不出现。（`ByrdonisNest.cs`；`Models.Cards/ByrdonisEgg.cs:25`）
→ 事件奖励不止是数值，而是在后续系统（休息处）里开一个新选项。

### 9.5 水晶球（Crystal Sphere）——自带小游戏的事件

**出现**：第 2 幕起、所有玩家金币 ≥100（`Models.Events/CrystalSphere.cs:IsAllowed`）。

**入口选项**

| 选项 | 代价 | 占卜次数 |
|---|---|---|
| 揭幕未来 | 50 + `NextInt(1,50)` = **51–99 金** | 3 |
| 分期付款 | 获得诅咒「债务」（回合结束在手牌中失去 10 金） | 6 |

（`CrystalSphere.cs:_uncoverFutureCost,CalculateVars,_paymentPlanCount`；`Models.Cards/Debt.cs:17`）

**棋盘**（`Events.Custom.CrystalSphereEvent/CrystalSphereMinigame.cs`）：

- 11×11 格；四个角各预先揭开曼哈顿距离 ≤2 的 6 格，共 24 格，剩 97 格被雾遮住。
- 物品只能放在被遮住的空格上，随机放置，最多重试 10 次布局。
- 两种工具：**大幅占卜**揭开 3×3（9 格），**小幅占卜**揭开 1 格；每次点击消耗一次占卜，工具可随时切换。
- 一个物品**所有格子都被揭开**才算获得；奖励在占卜用完后统一发放（诅咒在揭开时立即入组）。

| 物品 | 数量 | 尺寸 | 奖励 | 出处 |
|---|---|---|---|---|
| 遗物 | 1 | 4×4 | 随机遗物 | `CrystalSphereItems/CrystalSphereRelic.cs:11` |
| 普通药水 | 2 | 1×3 | 普通药水 | `CrystalSpherePotion.cs:22-30` |
| 稀有药水 | 1 | 2×2 | 稀有药水 | 同上 |
| 卡牌（普通/罕见/稀有） | 各 1 | 2×2 | 该稀有度 3 选 1 | `CrystalSphereCardReward.cs:35,47` |
| 诅咒 | 1 | 2×2 | 疑虑（回合结束在手牌中获得虚弱） | `CrystalSphereCurse.cs:13,20` |
| 小金币 | 5 | 1×1 | 10 金 | `CrystalSphereGold.cs:13,41` |
| 大金币 | 2 | 2×1 | 30 金 | 同上 |

物品共占 51 格 / 97 格。**关键推论**：4×4 的遗物四个角两两在某一维上相距 3，任何 3×3 都盖不住其中两个角，所以完整揭开遗物**至少要 4 次占卜**（推断，按源码几何）。「揭幕未来」只有 3 次，**永远拿不到遗物**；遗物只为「分期付款」准备——花 4 次挖遗物，剩 2 次挖别的。

→ 这是一个「信息不完全 + 资源分配」的小谜题：付金币得安全但少的次数，背诅咒得更多次数和唯一的大奖。用物品尺寸 vs 工具尺寸的几何关系去「锁」奖励，比写死规则更优雅。

## 10. 先古之民（9 个 AncientEventModel）

### 10.1 何时出现

|---|---|---|---|
| 第 1 幕 | 涅奥（Neow，「复生之母（被放逐）」） | 涅奥纪元未揭示时无先古之民，起点改怪物房 | `Models.Acts/Overgrowth.cs:26,100`；`Underdocks.cs:22` |
| 第 2 幕 | 欧洛巴斯（Orobas，「活体虹光」）、佩尔（Pael，「融化巨龙」）、特兹卡塔拉（Tezcatara，「饲火者」）+ 可能的达弗 | 欧洛巴斯需欧洛巴斯纪元 | `Hive.cs:24-28,98` |
| 第 3 幕 | 诺奴佩普（Nonupeipe，「机缘的化身」）、坦克斯（Tanx，「嵌合兽之王」）、瓦库（Vakuu，「第一个恶魔」）+ 可能的达弗 | 无 | `Glory.cs:23-28` |

**达弗的插入**：开局对共享先古之民列表（目前只有达弗）洗牌，第 2 幕取 `NextInt(列表长+1)` 个，剩下的给第 3 幕再取一次（`Runs/RunManager.cs:751-760`）。只有达弗时：50% 进第 2 幕候选，25% 进第 3 幕候选；再在候选里等概率抽一个，所以达弗**实际出现**的概率约第 2 幕 12.5%、第 3 幕 6.25%（全解锁时；推算）。

**进场效果**：所有先古之民在事件开始前把玩家**回满血**（进阶 2「旅途劳顿」为缺失量的 80%）；涅奥会先把 HP 置 0 再回，所以开局 HP 就是这个回复量（`Models/AncientEventModel.cs:172-191`，进阶判断在 :182）。这替代了一代的幕间回血。

还有一个 `Hook.ShouldAllowAncient` 能整体屏蔽先古之民（被屏蔽时显示 `WAX_CHOKER.blockMessage`，只给「继续」），但当前版本没有任何模型实现它（`AncientEventModel.cs:InitialDescription,GenerateInitialOptionsWrapper`）——蜡制项圈改名成玩具盒（`patch_notes/2026_01_15.md:178`）后留下的悬空 key，见第 08 章。

**设计观察**
- **「三池各一」= 保证三个选项是三种不同方向**（如瓦库：池 1 偏收益、池 2 偏防御/代价、池 3 偏规则改写——推断）；「大池取三」（诺奴佩普、坦克斯）则保证主题统一（坦克斯全是武器）。
- **条件项看牌组**：佩尔看可附魔/可移除张数、特兹卡塔拉看有没有基础打击、坦克斯/诺奴佩普看可附魔张数——先古遗物的「对症」由生成器保证，而不是让玩家碰运气。
- **涅奥的「1 坏 2 好」**：始终有一个带代价的强力选项，并用互斥表避免「代价和收益互相抵消」的无意义组合（如诅咒珍珠 + 金色珍珠）。

### 10.3 对话

先古之民有独立的对话系统：按「角色 × 第几次拜访（VisitIndex）」给不同对白，另有不分角色的通用对白和「r」后缀的可重复对白（`Entities.Ancients/AncientDialogueSet.cs:5-30`）。简中 `ancients.json` 里每个先古之民 32–53 条台词 key（`ch05_ancients.csv`）。叙事随拜访次数推进，是 Roguelike 里「同一 NPC 反复见面」的标准做法。

## 11. 可借鉴（汇总）

1. **经济总量在生成期锁死，玩家只选路线**：每幕精英/商店/? 的总数固定，路线差异给风险偏好空间（零精英路线 vs 3 精英路线）。
2. **用算法定义「无意义选择」并删除**（MapPathPruning）——可测试、可回归。
3. **所有「伪随机」都带保底且公式透明**：卡牌稀有度、药水、? 房三套系统同一思路（没中就涨、中了归位），实际体验比名义概率稳定得多。
4. **Boss 奖励前移到下一幕开头**（先古之民）：奖励和回血绑定在「新章开场」，节奏上是「收获-出发」而不是「打完-收工」。
5. **进阶的经济惩罚精准到杠杆**：通货膨胀只涨删牌、贫穷只砍收入、稀缺只砍稀有率——每一级改一个旋钮，便于玩家理解与平衡。
6. **事件=页面状态机 + 显式风险标注**（`ThatDoesDamage` / `ThatWillKillPlayerIf` / 锁定选项），信息透明是推运气事件好玩的前提。
7. **任务卡 + Hook 改写后续内容**：不写任务系统，用一张不可打出的卡挂 `ModifyGeneratedMap` / `ModifyNextEvent` 就实现跨幕剧情。
8. **小游戏用几何锁奖励**（水晶球的 4×4 遗物 vs 3×3 工具），规则自洽，玩家能自己推理出最优解。
